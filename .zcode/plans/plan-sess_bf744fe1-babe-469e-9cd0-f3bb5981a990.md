# Чат с Groq-агентом внутри приложения: действия над Kanban и данными 360

## 1. Динамические колонки (пререквизит «создаёт новые колонки»)
- **migration003**: таблица `kanban_columns` (name TEXT PK, position INTEGER, created_at), наполнение исходным списком из `service.ColunasValidas`.
- `db.ColumnRepo`: List/Add/Delete (+ порядок). Удаление колонки запрещено, если в ней есть карточки (иначе — ошибка «перенесите карточки»).
- `GetColunas` теперь читает из БД; `CriarColuna(nome)` / `RemoverColuna(nome)` — новые биндинги. Валидация в `SaveTicket`/`MoveTicket` переключена на список из БД (статический список остаётся только как источник для наполнения; триггер «Cobrança» работает по имени колонки).
- Тесты: миграция 003 наполняет 11 колонками, добавление/удаление, запрет удаления непустой.

## 2. Groq-агент с инструментами (`internal/service/agent.go`)
- Диалог с Groq через OpenAI-совместимый **function calling** (llama-3.3-70b-versatile поддерживает tools). Цикл: сообщение → вызовы инструментов (максимум 6 итераций) → финальный ответ.
- Определение `AgentTools` в service (схемы JSON), **исполнение** — через интерфейс `ToolExecutor`, реализованный в main (app) — без цикла импортов.
- Инструменты:
  - `buscar_cliente_360 {query}` — поиск по коду/имени;
  - `importar_cliente {codService, coluna}` — карточка из данных 360;
  - `listar_colunas {}`, `criar_coluna {nome}`;
  - `financeiro_cliente {codService}` — баланс/штрафы/счета;
  - `avaliar_cliente {ticketId}`;
  - `listar_tickets {coluna?}`, `mover_card {ticketId, coluna}`;
  - `gerar_proposta {ticketId}` — по активному соглашению.
- Каждое выполненное действие возвращается на фронт списком `acoes` («добавил клиента X в колонку Y», «создал колонку Z»).

## 3. Биндинг и безопасность
- `EnviarChat(historicoJSON, mensagem) → {resposta, acoes}` — без сохранения состояния: фронт присылает последние ~10 сообщений. Тайм-аут 60 с.
- Все мутации идут через те же валидируемые биндинги приложения (без новых путей записи в БД в обход проверок); ключ — только из настроек; без ключа чат сообщает, где его ввести.

## 4. Фронтенд
- `ChatDrawer.tsx`: выдвижная панель чата (кнопка 💬 в шапке), история, ввод, отображение выполненных действий под ответом, обновление доски после мутаций (`GetTickets` заново).
- wails-types: алиасы сгенерированных типов (ChatResult и т.д.).

## 5. Тесты и релиз
- Go: agent loop на мок-сервере Groq (ответ с tool_call → результат → финальный текст; лимит итераций), колонки, executor-инструменты через httptest-360. vitest: рендер чата на моках. govulncheck/npm audit.
- `wails build -clean -trimpath` → rota-smart.exe, smoke-тест.
