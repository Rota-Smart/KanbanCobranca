# Plano: voz no chat + ações do agente em tickets do 360

App: Wails (Go) + React/TS. Sem testes de escrita no 360 real — apenas checagens de compilação (`go build ./...`, `go vet`, `tsc`, vitest existentes).

## 1. Fala→texto no chat (Vosk local, open source)
- Dependência: **vosk-browser** (WASM, MIT/Apache) no frontend — roda offline dentro do WebView2, sem cgo/dll no Go.
- `ChatDrawer.tsx`: botão 🎤 ao lado do input. Ao clicar: pede microfone via WebAudio, cria `KaldiRecognizer` streaming, resultado parcial/final vai direto para o input da mensagem. Clique de novo para parar.
- Modelo: `vosk-model-small-pt-br` (~46 MB), **não embutido no exe**. Fica em `UserConfigDir/RotaSmart/vosk-model/`. Backend:
  - binding `ModeloVozInfo()` (existe? versão?) e `DefinirModeloVoz()` com diálogo de pasta — copia a pasta escolhida para UserConfigDir;
  - config key nova `vosk_model`;
  - handler no AssetServer do Wails servindo os arquivos do modelo do disco para o frontend fazer fetch;
  - seção em `Configuracoes.tsx` com link para download do modelo e botão de seleção.
- Sem modelo configurado → toast explicando onde baixar.

## 2. Tools novas do agente (internal/service/agent.go + app_chat.go)
Registrar schemas em `AgentTools()` e cases no switch de `ExecutarAgente` (padrão existente, 12 tools → 15):
- **`abrir_ticket_360`** (número/cod_service/cliente): busca o ticket no kanban local (`ticket_repo`) e/ou na fila do 360 para obter o uuid → monta URL `https://360.rotagroup.com.br/helpdesk/tickets/<uuid>`.
  - **Mecanismo principal (a pedido do usuário): colar na aba atual** — novo pacote `internal/tela` (extensão): via UIA localizar a janela do Chrome com aba do 360, ativá-la, simular `Ctrl+L` + colar URL + Enter. Reusa a infra de UIA já existente (Shift+F2).
  - Fallback: `browser.OpenURL` (navegador padrão, nova aba na mesma janela).
- **`responder_ticket_360`** (uuid/número + texto): novo método `rota360.Cliente.ResponderTicket` — POST na API do 360. Endpoint a inferir na implementação (inspecionando o bundle do site helpdesk com o cookie existente; provável `/api/helpdesk/tickets/<uuid>/interacoes`). Permite o fluxo: "melhore o texto do ticket X adicionando <info> e envie" — o system prompt instrui o agente a reescrever quando pedido.
- **`alterar_status_ticket_360`** (uuid/número + status): novo método `AlterarStatusTicket` (PATCH/PUT no ticket). Valores de status: o agente lê os status válidos do próprio `detalhe_ticket_360` (que já retorna o status atual) e usa os nomes exatos que a API devolve.
- **`systemAgente`** atualizado: descreve as 3 capacidades novas e a orientação de aprimorar redação de tickets (tom profissional, claro, sem apagar dados técnicos).

## 3. Frontend
- Só o 🎤 no `ChatDrawer.tsx` + seção de modelo de voz nas Configurações. Ações de ticket acontecem via chat (o agente chama as tools; o usuário vê o resumo como nas ações atuais).

## 4. Verificação (sem tocar no sistema real)
- `go build ./... && go vet ./...`, `go test ./...` (testes existentes), `tsc` + vitest do frontend.
- **Nenhuma chamada de escrita ao 360** (responder/alterar status) será executada — nem manual nem em teste. As ferramentas ficarão prontas para uso real pelo usuário no app.
- Sem bump de versão/empacotamento nesta entrega (decisão de release fica para depois).
